# 第 12 课逐页脚本｜Agent/Skill 背后的逻辑与个人工作流设计

## 一、使用说明

### 本课唯一主目标

> 学生为自己的真实科研动作设计一份可审计的个人 Agent Workflow。

本课不追求在 90 分钟内讲透所有 Agent 架构，也不把任何现成 Skill 的安装和调用当作学习目标。八要素框架用于拆解现成工具；贯穿案例用于演示设计结果；个人实践用于把"我会用 Agent"升级为"我能设计并审计一个工作流"。

### 适用条件

- 21-40 人；
- 连续 90 分钟；
- 中文授课，英文仅保留论文名、工具名和必要术语；
- 正式 PPT 继承 [交大模版.pptx](../../references/library/template/交大模版.pptx) 的母版、版式、字体与品牌元素；
- OpenCode、Git 和模型后端尽量在课前完成环境确认；
- 学生携带个人项目中一个真实科研动作；
- 本课无正式提交，产出为第 13 课验证门前置状态。

## P01｜你最近用的 Agent，是谁替你做的决定

### 屏显内容

你最近一次用一个 Agent 或 Skill 完成科研动作时，是谁决定了：

- 它能读哪些文件？
- 它能写哪些目录？
- 它什么时候停？
- 失败了怎么办？

> 调用不等于看懂。

### 视觉结构

左侧四个问题，右侧一个空白的"拆解卡"轮廓占主体。不用等宽卡片矩阵。

### 教师讲述备注

开场放下工具清单。本课不要求你装更多 Skill，而是要求你看懂一个现成 Agent 隐含的设计决定。这些决定如果是别人替你做的，你的研究动作边界就让渡给了一个你未审计的配置。

### 互动／操作

请学生举手：最近一次用 Agent 时，是否看过它的权限声明或停止条件？只听回答，不评价。

### 建议时间

0:00-1:30。

### 来源与事实边界

课程定位以 [curriculum.md](../../course/curriculum.md) 第 4-5 条为准。

## P05｜要素 1：任务契约——它到底在做什么

### 屏显内容

任务契约：输入｜输出｜成功标准｜不适用范围

AutoResearch 示例：

- 输入：研究问题 + 配置
- 输出：实验报告 + 日志
- 成功标准：指标达成阈值
- 不适用范围：？

> 不写不适用范围，边界就由模型自决。

### 视觉结构

左侧拆解卡"任务契约"格填入 AutoResearch 实例，右侧对照"我的工作流"空格。

### 教师讲述备注

先看现成对象的任务契约。AutoResearch 写了输入输出和成功阈值，但不一定写不适用范围。这正是我们要学的：契约只写目标不写非例，使用者容易在边界外误用。

### 互动／操作

请学生指出 AutoResearch 契约里缺的非例。

### 建议时间

6:00-8:00。

### 来源与事实边界

AutoResearch README 与 `program.md`。

## P06｜要素 1（续）：把模糊意图收敛为可审计契约

### 屏显内容

模糊意图：帮我把相关论文整理一下。

任务契约改写：

- 输入：按证据角色标注的论文清单（≤30 篇，每篇 DOI + PDF）

- 成功标准：每条主张可定位到原文页码

## P07｜要素 2-3：Context 与 Memory——给它看什么、记在哪

### 屏显内容

Context：当前任务明确提供的材料与状态（不是"能看就看"）

Memory：跨步骤保留的状态（优先可审计工件，而非会话记忆）

> 关掉会话后仍能复原当时状态，才算可审计 Memory。

### 视觉结构

左侧一个会话气泡轮廓（不可审计），右侧一个工件树 `evidence-map.md` / `experiment-log.md` / `ai-usage-log.md`（可审计）。

### 教师讲述备注

AutoResearch 把状态写在文件和日志里，这是它的优点。会话记忆可作为缓存，但不能是唯一来源。Context 选择本身是研究判断，要记录为什么纳入、为什么排除。

### 互动／操作

请学生判断：你最近一次用 Agent 时，状态主要存在哪？

### 建议时间

10:00-12:00。

### 来源与事实边界

[第 1 课讲义 §四](../lesson-01/handout.md)；[starter-template.md](../../course/starter-template.md) AI 使用记录字段。

## P11｜要素 5：执行循环——它怎么走、怎么停

### 屏显内容

执行循环：计划→行动→观察→评价→停止

停止条件：任务完成？预算耗尽？人喊停？

> 不是所有任务都需要自主循环。

### 视觉结构

## P12｜要素 5（续）：六种工作流模式

### 屏显内容

| 模式 | 适用 |
| --- | --- |
| prompt chaining | 步骤清楚、每步可验收 |
| routing | 输入分类后走不同分支 |
| parallelization | 独立子任务可同时跑 |
| orchestrator-workers | 子任务动态分配 |
| evaluator-optimizer | 有明确评价器可迭代 |
| autonomous agent | 步骤不可预定、需观察后决策 |

### 视觉结构

六行模式表，每行配一个极简结构图标。不展开每模式的实现细节。

### 教师讲述备注

这六种模式来自 Anthropic *Building Effective Agents* 工程博客，不是经典理论。引用时标注来源。选用时先看可控性和可审计性，再看能力。

### 互动／操作

请学生把自己的工作流对号入座。

### 建议时间

20:00-22:00。

### 来源与事实边界

Anthropic, [*Building Effective Agents*](https://www.anthropic.com/engineering/building-effective-agents)。标注为工程博客，非学术论文。

## P14｜取舍：脚本、工作流、Agent、复杂系统

### 屏显内容

| 形态 | 适用 | 风险 |
| --- | --- | --- |
| 确定性脚本 | 步骤清楚、无模型判断 | 错误时全链失败 |
| 固定工作流 | 步骤可预定、每步需模型能力 | 步骤错误级联 |
| 单 Agent | 步骤不可预定、需观察后决策 | 难停止、难审计 |
| 更复杂系统 | 多 Agent 协作、长 horizon | 课程不要求，需说明必要性 |

> 自主循环不等于高级，固定链的可审计性常被低估。

### 视觉结构

四行对照表，配一句主结论。

### 教师讲述备注

学生容易把自主 Agent 当作默认"高级"形态。本课强调：可审计性优先于自主性。

### 互动／操作

无。

### 建议时间

26:00-30:00。

### 来源与事实边界

[handout.md §三](./handout.md)。

## P15｜要素 6：工件与追踪——一次运行留下什么

### 屏显内容

一次运行至少留下：

- 任务契约
- Context 清单
- 工具调用记录
- 中间结果
- diff
- 人工审核记录

> 关掉会话后能否从一条结论追到当时 Context 和 prompt？

### 视觉结构

真实或重绘的研究仓库树占主体：`agent-workflow/runs/` 下含 `contract.md`、`context.csv`、`tool-calls.log`、`diff.patch`、`review.md`。

### 教师讲述备注
