# 智能科研方法——详细备课规划

本文件是 16 次课的教学执行指南。课程设计、门条件和评分的规范来源分别是：

- [syllabus.md](../ai-research-workflow-course/syllabus.md)
- [assignments.md](../ai-research-workflow-course/assignments.md)
- [assessment.md](../ai-research-workflow-course/assessment.md)

如三者与本文件不一致，先修正课程设计文档，再同步本文件，不在课堂材料中另立规则。

## 一、执行原则

1. 课程主线是八阶段研究链路，不是 AI 工具清单。
2. OpenCode 从第 1 课起作为主要课堂工作平台，但不限制模型或后端，也不因平台选择加分。
3. 不以安装、记忆或调用现成 Skills 为教学目标。案例用于分析任务契约、Context、Memory、工具与权限、状态与工件、执行循环、Evals、人工审核点和失败恢复。
4. 每位学生独立维护项目仓库、证据、判断、实验、个人 Agent Workflow、AI 使用记录和反思。
5. 3-4 人固定同伴组只用于课堂分享、互查和同行评审，不共同提交。
6. 正式提交只有四次：第 6、9、13、16 课。第 8 课分享和第 15 课预检是形成性活动，不增加正式作业。
7. AI 输出只是线索。关键结论至少绑定一项可核验的直接证据或实验结果及上游决定；`stable` 结论原则上有两项相互独立的证据。
8. 伦理、权限、可追溯性、失败记录和人工核验贯穿所有课次。

## 二、总体节奏

| 模块 | 课次 | 学时 | 核心问题 | 阶段产出 |
| --- | --- | ---: | --- | --- |
| 课程框架、平台与规范 | 1-2 | 4 | 如何安全、可审计地用 Agent 支撑科研？ | 项目工作区、链路草图、权限矩阵、伦理清单 |
| 文献、证据与问题 | 3-6 | 8 | 如何从外部输入形成可检验问题？ | 检索记录、阅读卡、证据地图、问题门材料 |
| 假设、判断与方案分享 | 7-9 | 6 | 如何把问题变成有依据的实验规格？ | 机制假设、研究判断、分享反馈、判断门材料 |
| 原型、自动化与个人工作流 | 10-13 | 8 | 如何实现、评价并约束一个科研工作流？ | 原型、实验记录、个人 Agent Workflow、验证门材料 |
| 回写、评审与表达 | 14-16 | 6 | 如何把结果写成可追溯论证？ | 论文式短文、评审记录、论证门与期末项目 |

每次课 90 分钟，默认节奏：

- 回顾与工件检查：5-10 分钟
- 方法讲授与案例：25-35 分钟
- 演示或诊断：15-20 分钟
- 个人实践与同伴反馈：25-35 分钟
- 回写与退出卡：5 分钟

“课堂产出”默认回写到持续项目，不等于正式提交。

## 三、课堂环境与项目组织

### OpenCode 起步环境

第 1 课前准备一份最小启动说明，覆盖：

- 安装与启动方式，以及无法安装时的浏览器/远程替代方案
- 课程项目目录和 `AGENTS.md`
- 模型与后端选择原则：可用、合规、成本可控、能够保留必要记录
- 默认只读范围、允许写入的项目目录、命令执行确认和网络访问边界
- AI 使用记录、工件状态表和 Agent 权限矩阵
- 一次最小任务演示：读取课程说明，生成链路草图建议，由学生审核后写入项目文件

不要把第 1 课变成安装排障课。预先准备环境检查脚本、截图版备用演示和两人临时共用设备方案；课堂产出仍由每位学生写回自己的仓库。

### 个人项目与同伴组

- 每人一个仓库或明确隔离的个人目录。
- 同伴组固定 3-4 人，主要用于第 6、8、9、13、15、16 课的检查与反馈。
- 反馈必须留下记录，但反馈者不替代作者修改。
- 高计算量项目若申请双人协作，应分别提交个人研究判断、个人 Agent Workflow、AI 使用记录和反思；是否批准由教师在问题门前确认。

## 四、逐课备课

## 第 1 课｜AI 辅助科研导论、OpenCode 与八阶段研究链路

教学目标：

- 区分“生成一份报告”和“完成可审查的科研闭环”。
- 说出八阶段研究链路及四个研究门。
- 启动个人 OpenCode 工作区，完成最小可审计交互。

90 分钟建议：

| 时间 | 活动 |
| --- | --- |
| 0-15 | 课程目标、个人项目、四次正式提交和同伴组说明 |
| 15-30 | 八阶段链路与四门总览；用一篇短论文反向拆解 |
| 30-45 | OpenCode 平台、模型后端、权限边界和记录要求 |
| 45-60 | 教师演示：AI 建议如何进入人工审核，再写回工件 |
| 60-82 | 学生建立个人工作区、问题初稿和链路草图 |
| 82-90 | 同伴互看与退出卡 |

课堂产出：个人工作区、问题方向、八阶段链路草图。
课后推进：完善初步问题，不正式提交。

## 第 2 课｜科研伦理、Agent 权限与研究工件

教学目标：

- 能识别数据、引用、署名、隐私、双重用途和 AI 使用风险。
- 能写出 Agent 权限矩阵与人工确认点。
- 理解 `draft → review → approved → stable` 的用途。

核心活动：

- 对三个伦理案例做“允许 / 有条件允许 / 禁止”判断。
- 比较过宽权限和最小权限的两个 Agent 配置。
- 建立 `ai-usage-log.md`、`agent-permissions.md` 和伦理清单。

强调：未公开材料、学生资料和敏感数据不得默认发送给外部模型；Agent 不得自行扩大访问范围、修改评价协议或删除失败记录。

课堂产出：权限矩阵、伦理清单、AI 使用记录初版。
课后推进：根据选题补全风险边界，不正式提交。

## 第 3 课｜文献检索与证据角色

教学目标：

- 从研究问题生成可复盘的关键词、检索式和筛选条件。
- 区分主证据、补充证据、对比证据与探索线索。
- 回到原始来源核验 AI 检索结果。

核心活动：

- 从一个宽泛主题逐步构造检索式。
- 对同一问题的 AI 综合报告和原始论文列表做来源审计。
- 学生为自己的项目建立候选文献表和纳入/排除理由。

课堂产出：检索记录、候选文献表、证据角色初标。
课后推进：继续筛选和回源，不正式提交。

## 第 4 课｜AI 辅助精读与主张核验

教学目标：

- 提取论文的问题、方法、设置、结果、局限和可复现信息。
- 识别 AI 错读、过度概括和伪造引用。
- 建立“原文位置—主张—人工判断”的追踪关系。

核心活动：

- 教师示范一次结构化精读。
- 学生审计一份故意含错误的 AI 摘要。
- 为关键论文建立阅读卡，记录页码、图表或章节位置。

课堂产出：2-3 张阅读卡和一条错读审计记录。
课后推进：扩展关键论文阅读，不正式提交。

## 第 5 课｜综述结构、证据地图与研究空白

教学目标：

- 从摘要堆叠转向按冲突、条件和机制组织综述。
- 识别冲突空白、缺角空白和新问题空白。
- 说明现有证据支持什么、不能支持什么。

核心活动：

- 将五篇文献从“按论文排列”重组为“按研究问题排列”。
- 绘制证据地图，显式保留冲突和缺失证据。
- 对问题门材料做第一次同伴诊断。

课堂产出：证据地图初版、研究空白候选。
课后推进：准备问题门材料，不单独提交。

## 第 6 课｜问题定义、第一性原理与问题门

教学目标：

- 把宽泛兴趣改写为范围清楚、可证伪、周期可完成的问题。
- 从基本约束推导必要条件和可检验前提。
- 完成问题门正式提交。

90 分钟建议：

| 时间 | 活动 |
| --- | --- |
| 0-25 | 问题重写、非例和可证伪命题 |
| 25-40 | 第一性原理推导示范 |
| 40-60 | 个人修改 |
| 60-78 | 同伴组按门条件检查 |
| 78-90 | 提交说明、失败后的回退路径 |

正式提交 1：问题门材料。具体条件以 [assignments.md](../ai-research-workflow-course/assignments.md) 为准。

## 第 7 课｜机制假设、研究判断与实验设计

教学目标：

- 将问题拆成机制假设和可观察指标。
- 区分事实、假设、研究判断和待验证项。
- 写出 baseline、对照、变量、指标和失败预案。

核心活动：

- 对一个研究问题生成多个候选假设，并由学生说明淘汰理由。
- 使用研究判断记录比较两种方案。
- 建立“假设—指标—实验—可能结论”的映射。

强调：Agent 建议只能生成候选项，最终机制判断由学生负责。

课堂产出：机制假设、研究判断、实验方案初版。
课后推进：准备第 8 课口头方案，不正式提交。

## 第 8 课｜学生研究方案分享与设计诊所

教学目标：

- 用有限时间清楚表达问题、证据、假设和验证路径。
- 从跨项目反馈中发现范围、证据或实验设计缺陷。
- 将反馈转化为明确的修改决定。

组织方式：

- 每位学生 3 分钟陈述：问题、关键证据、机制假设、最小验证和最大风险。
- 2 分钟同伴反馈：一项最强处、一项最大风险、一条可执行建议。
- 同伴组使用统一 rubric，不评“题目是否时髦”，只检查可检验性、证据、可行性和边界。

课堂产出：分享页、反馈记录、采纳/不采纳决定。
本课不新增正式提交。

## 第 9 课｜Baseline、实验规格、可复现性与判断门

教学目标：

- 定义可解释的 baseline 和公平对照。
- 固化环境、配置、随机性、实验 ID、指标和停止条件。
- 将成熟内容迁移到完整项目模板并通过判断门。

核心活动：

- 审计一个“能跑但不可复现”的实验。
- 完成实验规格和最小复现说明。
- 检查研究判断能否追溯到机制假设和证据地图。

正式提交 2：判断门材料。提交后开始使用 [project-template.md](../ai-research-workflow-course/project-template.md)。

## 第 10 课｜AI 辅助编码、调试与受限 Agent

教学目标：

- 把代码任务写成带验收标准的任务契约。
- 控制文件写入、命令执行、测试和人工 review。
- 区分修复根因、绕过失败和污染实验。

核心活动：

- 比较模糊 prompt 与任务契约。
- OpenCode 演示：只允许修改目标文件、运行指定检查、保留 diff 和失败日志。
- 学生为自己的原型完成一个受限编码或调试任务。

课堂产出：任务契约、代码 diff、验证记录和失败记录。
课后推进：完善原型，不正式提交。

## 第 11 课｜实验自动化与 AutoResearch 循环

教学目标：

- 理解 `Edit → Evaluate → Keep/Discard → Repeat` 的适用条件。
- 为自动迭代设置固定指标、预算、停止条件和回退机制。
- 避免选择性报告和评价协议漂移。

核心活动：

- 拆解 AutoResearch 案例，不追求复刻完整系统。
- 将一个可重复科研动作改写为受限循环。
- 检查失败结果是否保留、指标是否可被工作流篡改。

课堂产出：自动化循环设计、预算和停止条件。
课后推进：运行最小实验队列，不正式提交。

## 第 12 课｜Agent/Skill 背后的逻辑与个人工作流设计

教学目标：

- 能从现成 Agent/Skill 中抽取可迁移的设计逻辑。
- 能说明何时用确定性脚本、workflow、单 Agent 或更复杂系统。
- 完成个人 Agent Workflow 的设计与最小实现。

分析框架：

| 维度 | 核心问题 |
| --- | --- |
| 任务契约 | 输入、输出、成功标准和不适用范围是什么？ |
| Context / Memory | 使用哪些材料，状态如何保存和更新？ |
| 工具与权限 | 能读、写、执行和联网到什么范围？ |
| 执行循环 | 如何计划、行动、观察、评价和停止？ |
| 工件与追踪 | 输入、日志、输出和上游决定如何关联？ |
| Evals | 与什么 baseline 比，用什么指标或 rubric？ |
| 人工审核 | 哪些判断和外部动作必须确认？ |
| 失败恢复 | 超时、无效输出、工具失败或越权时怎么办？ |

课堂产出：个人 Agent Workflow 说明、可运行或可演示原型、评价计划。
课后推进：执行评价并记录至少一个失败或局限，不正式提交。

## 第 13 课｜工作流评价、结果分析、失败审计与验证门

教学目标：

- 评价工作流是否改善目标科研动作，而不只是“能够运行”。
- 将实验结果映射回假设、判断和证据。
- 完成失败分析、有效性威胁和验证门提交。

评价至少选择适合项目的维度：

- 正确性与可追溯性
- 时间或成本
- 失败率
- 人工修订量
- 权限越界或风险
- 相对 baseline 的改善

正式提交 3：验证门材料，包含个人 Agent Workflow 的运行、评价和失败记录。

## 第 14 课｜论文式写作、证据回写与 AI 使用披露

教学目标：

- 形成“主张—证据—推理—边界”的论证结构。
- 将验证结果回写到研究判断和证据地图。
- 正确披露 AI 对检索、代码、实验和写作的参与。

核心活动：

- 审计一段流畅但证据断裂的 AI 文本。
- 用证据编号和实验 ID 重写摘要或结果段。
- 检查 `stable` 结论的独立证据与限制说明。

课堂产出：论文式短文初版、结论追踪表、AI 使用披露。
课后推进：准备同行评审，不正式提交。

## 第 15 课｜同行评审、论证门预检与修改

教学目标：

- 按统一 rubric 检查论证链、可复现性、工作流评价和伦理边界。
- 区分致命问题、重要问题和表达建议。
- 形成具体修改清单和回应。

90 分钟建议：

| 时间 | 活动 |
| --- | --- |
| 0-15 | 评审校准：共同评分一个匿名样例 |
| 15-50 | 同伴交叉评审 |
| 50-65 | 作者澄清与口头回应 |
| 65-82 | 论证门逐项预检 |
| 82-90 | 最终修改优先级与提交提醒 |

课堂产出：同行评审表、回应记录、修改清单。
本课不正式提交，论证门与期末项目合并到第 16 课。

## 第 16 课｜学生最终分享、论证门与期末项目

教学目标：

- 用可核验证据回答研究问题并说明边界。
- 展示个人 Agent Workflow 的真实作用、失败和人工判断。
- 完成论证门和期末项目合并提交。

展示必须回答：

1. 研究问题和关键判断是什么？
2. 哪些证据或实验支持、反驳或尚不能判断？
3. 个人 Agent Workflow 改善了哪个科研动作，如何评价？
4. AI 在哪里有效、哪里误导、如何核验？
5. 当前结论的适用边界与下一步是什么？

正式提交 4：论证门 + 期末项目。教师可抽查一次复现、一个引用或一条工作流 trace。

## 五、材料包与制作优先级

逐课材料按 [projects/README.md](./README.md) 的四类体例制作：学生正式讲义、教师教案、正式课堂 PPT、课堂活动材料。试讲材料只用于开课评审和历史追踪，不计入正式课程完成度。

| 优先级 | 材料包 | 主要课次 | 最小可交付内容 |
| ---: | --- | --- | --- |
| P0 | 课程起步包 | 1-2 | 正式讲义、教师教案、正式课堂 PPT、OpenCode 启动说明、项目骨架、权限矩阵、伦理案例、AI 使用记录 |
| P0 | 四门检查包 | 6、9、13、16 | 学生清单、教师 rubric、未通过后的回退说明 |
| P0 | 第 8 课分享包 | 8 | 3 分钟模板、2 分钟反馈卡、课堂排程表 |
| P1 | 文献与证据包 | 3-5 | 检索练习、错读案例、阅读卡、证据地图样例 |
| P1 | 假设与实验包 | 7、9 | 假设拆分、判断记录、baseline 审计、实验规格 |
| P1 | Agent Workflow 包 | 10-13 | 任务契约、权限案例、循环案例、工作流 canvas、评价样例 |
| P1 | 写作与评审包 | 14-16 | 证据断裂反例、追踪表、评审表、展示 rubric |
| P2 | 延伸案例包 | 1、5、11、12 | Deep Research/STORM、AutoResearch、AI Scientist 等对比材料 |

正式讲义应面向学生并可独立阅读，包含方法解释、完整案例、练习或自测、术语与来源入口。教师教案负责 90 分钟教学组织。正式 PPT 以中文为主，可保留必要英文术语、论文标题和工具名；它应从正式讲义与教案提炼，而不是复制或改名试讲 PPT。每份 PPT 制作后需渲染检查，并同时准备课堂练习的可编辑版本。

## 六、双引擎备课协作

教师可使用 Claude Code 与 Codex 双引擎，但每个工作包只能有一个主笔：

1. 主笔读取 `AGENTS.md` 和规范课程文件，完成初稿与自检。
2. 另一引擎按事实准确性、教学节奏、跨文档一致性、可执行性和表述口吻审阅。表述口吻维按 [review-checklist.md](./review-checklist.md) 逐项核对，重点去除 AI 生成痕迹（对仗句式过密、meta 自白、机械编号、标题腔），同时保留课程固有的结构化术语和限定式风格。
3. 主笔处理反馈并运行检查；两者不并发修改同一文件。
4. 重要来源、时间敏感信息和 PPT 渲染结果由人工最终确认。

建议按“课程起步、文献证据、问题假设、实验工程、Agent Workflow、写作评审”拆分工作包，而不是按工具或模型拆分。

## 七、课程运行检查点

### 开课前

- OpenCode 主要路径和备用路径都完成演练。
- 课程仓库、模板、门清单和同伴组机制已发布。
- 案例来源已回源核验，工具界面和时效性信息已更新。
- 所有 PPT 已渲染检查，练习材料可编辑。

### 每次课后

- 记录实际时间分配、学生卡点和需调整内容。
- 只收集本课课堂产出，不临时增加正式作业。
- 把共性问题回写到下一课开头，不为个别工具故障改变课程主线。

### 四个研究门

- 第 6 课：问题门
- 第 9 课：判断门
- 第 13 课：验证门
- 第 16 课：论证门与期末项目

门未通过时，只要求修复缺失条件并重新检查，不重复提交无关材料。

## 八、主要风险与预案

| 风险 | 预案 |
| --- | --- |
| OpenCode 安装或后端不可用 | 课前环境检查；准备远程/浏览器替代和录屏；不把排障计入学习目标 |
| 学生把课程理解为工具或 Prompt 课 | 每个案例必须映射到研究链路、工件、证据和人工判断 |
| Skills 演示变成照抄配置 | 要求反向分析设计逻辑，并为个人科研动作重新定义任务契约和评价 |
| 个人项目负担过大 | 正式提交限制为四次；第 8、15 课提供反馈但不新增作业 |
| 同伴组变成隐性小组作业 | 每人独立仓库和答辩；反馈留痕，作者独立决定和修改 |
| Agent 权限过宽或泄露敏感数据 | 默认最小权限；敏感目录禁止访问；外部发送和执行动作设人工确认 |
| 自动化只保留成功结果 | 固定评价协议、预算和停止条件；失败日志是验证门必查材料 |
| AI 生成文本掩盖证据缺口 | 关键结论绑定直接证据和上游决定；抽查原文、实验 ID 或 trace |
| 第 16 课分享时间不足 | 根据选课人数采用分会场、海报/演示轮转或课前短视频；论证门标准不变 |

## 九、完成标准

备课进入可授课状态需同时满足：

- 16 次课均有可独立阅读的学生正式讲义。
- 16 次课均有教师教案、中文正式课堂 PPT、课堂练习和退出卡；试讲材料不计入这一完成度。
- 四门检查表、评分 rubric、第 8 课分享表和第 15 课同行评审表可直接使用。
- OpenCode 最小演示和备用路径已实测。
- 课程设计、备课规划、项目模板、申请表中英文概要和考核口径一致。
- 所有交付文件完成链接、内容和视觉检查。
